### Written Reflection

One key design decision was keeping the MCP Gateway client, tool aggregation, and the Agent invocation all inside a single with client: context block, rather than fetching gateway tool definitions and closing the session before invoking the agent. Early on, I split these steps apart, which meant the MCP session was already torn down by the time the model tried to call a Gateway tool like get_order, producing an MCPClientInitializationError. Consolidating everything inside the context manager ensured the live session stayed open for the full lifetime of the request, since tool execution, not just tool discovery, depends on that connection.

The biggest challenge was diagnosing a chain of silent failures in the search_knowledge_base tool. Initially, a failed bedrock:Retrieve call was being swallowed because the tool had no exception handling, so the agent just reported a generic, sometimes inaccurate, explanation to the user (at one point fabricating loyalty-tier benefits from general knowledge instead of admitting the lookup failed). Adding explicit logging and a try/except around the Bedrock call surfaced the real AccessDeniedException, which traced back to the AgentCore runtime's execution role lacking bedrock:Retrieve permission on the newly created knowledge base ARN. This taught me that IAM errors caused by resource recreation (a new KB ID after switching vector store types) are easy to misdiagnose as configuration or code bugs if failures aren't logged explicitly.

For production, the most important consideration is tightening how the agent communicates tool failures. Right now, when a tool errors out, the model tends to speculate about the cause ("AWS permissions," "technical issue") even when it has no evidence for that explanation, and in some cases substitutes an answer from its own training data instead of admitting a gap. In a real deployment, unverified failure explanations and fabricated policy details could mislead customers or mask real operational issues. Enforcing stricter system-prompt rules, report only that a tool failed, never guess why, and never substitute general knowledge for retrieved data, would be essential before this agent handled live customer traffic.
